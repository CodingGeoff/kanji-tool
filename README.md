# 日语汉字学习工具

面向「平假名已掌握、汉字是短板」的学习者，目标：无障碍看懂日语字幕。

## 启动

```bash
pip install flask fugashi unidic-lite requests sudachipy sudachidict_core edge-tts
python3 app.py        # 打开 http://localhost:5000
```

## 功能对照需求

### 1. 语料获取（持续扩充，非固定例句）
- 三个公开免费渠道：**Tatoeba**（海量例句+中/英翻译）、**日文维基百科**、**维基新闻**（均为官方 API，随机抓取，永不重样）
- 后台线程自动持续抓取：语料 < 500 句时每分钟快速补充，之后每 10 分钟慢速扩充
- 页面上也可手动点按钮按渠道抓取
- 所有语料写入本地 SQLite（`kanji.db`）缓存并自动去重，学习复习一律优先读本地库，离线可用

### 2. 数据库能力
- SQLite 四张表：`sentences`（语料）/ `kanji_index`（汉字-例句索引）/ `srs`（复习记录）/ `history`（历史）
- 语料支持完整增删改查（搜索、手动添加、编辑重注音、删除）
- 「统计·历史」页记录每一次抓取/学习/复习/增删改操作

### 3. 汉字注音（重点）—— 五层防错架构
1. **MeCab(fugashi)+UniDic 词格 Viterbi 解码**：读音由整句上下文统计决定
2. **数词+助数词规则引擎**：修正 `10分→じゅっぷん / 3本→さんぼん / 1日→ついたち / 20歳→はたち` 等词典引擎的系统性盲区（含促音便、连浊、熟字训式融合读法）
3. **N-best 歧义检测**：`行った(おこなった/いった)` 类同形异音词自动标 ⚠ 并给出候选读音
4. **Sudachi 第二引擎交叉验证**：双引擎一致 → 高置信；词典级复合词仲裁修正连接处错误（`日本人→にほんじん` 而非 にっぽん+にん）
5. **未知词零猜测**：两个词典都查不到时明确标"读音未知"，绝不输出错误注音

回归测试：`python3 test_furigana.py`（78 项黄金标准断言全部通过）
引擎升级后可调 `POST /api/reannotate` 全库重新注音。


### 4. 艾宾浩斯复习
- 复习间隔：5分 → 30分 → 12时 → 1天 → 2天 → 4天 → 7天 → 15天 → 1月 → 2月
- 认识→进入下一记忆阶段；模糊→维持；忘记→曲线重置从头巩固
- 打开工具即自动推送到期汉字；例句从本地语料库**智能随机抽取**（优先带翻译、其他汉字大多已学过的句子，每次都不同）
- 「学新字」按语料真实频次推荐高频汉字，学习性价比最高


### 5. 例句朗读（TTS）
- 每个例句旁有 🔊 按钮（复习卡、语料库、汉字详情、字幕注音均支持）
- **6 种神经网络音色**（右上角切换）：七海/圭太（日语原生）+ Ava/Emma/Andrew/Brian（多语言），四档语速，选择自动记忆
- 发音由微软神经 TTS 按整句上下文决定，与注音引擎相互独立、互为校验
- 合成结果缓存本地 `audio_cache/`，同句同音色只合成一次，之后瞬时播放（符合本地缓存优先原则）
- 服务端不可用时自动退回浏览器本地日语语音


### 6. 高级模式：语法点全解析
- 右上角开启「高级模式」后，**点击任意句子**（复习卡/语料库/汉字详情/字幕注音）弹出语法解析
- 识别 JLPT **N5〜N1** 全级别语法点，**由浅入深排序**，等级徽章一目了然
- 等级过滤：点击 N5〜N1 彩色标签可隐藏/显示对应等级（比如屏蔽已掌握的 N5 基础项）
- 解析引擎基于**形态素特征匹配**（词性/词元/活用形三重约束），非字符串匹配：
  「で」是格助词还是て形浊化、「そう」是样态还是传闻、ませ**ん**与文语否定**ん**，全部由词典特征精确区分
- **三级零遗漏覆盖**：结构句型库（80+条规则）→ 单体功能词兜底表（全部常见助词/助动词）→ 完备性扫描（未收录的功能词也明确标出，绝不静默跳过）
- 解释生成：多套措辞模板 × 句子指纹 × 引用句中实际上下文——同一语法点在不同句子里讲法各不相同


### 7. 数据质量防线
- 入库三重校验：垃圾字符拒绝（下划线/时间戳/测试标记）→ 内嵌注音自动剥离修复（`日本にっぽん語ご` → `日本語`，最小剥离+词典读音验证+≥2处才触发，正常句零误伤）→ 格式过滤
- 「🧹清理脏数据」一键扫描全库修复/删除；「💾备份数据库」一键下载 kanji.db

### 8. 收藏夹（完整增删改查）
- 句子收藏：语料库/RAG结果/复习卡随处 ☆ 一键收藏，支持笔记、移除
- 词汇收藏：输入即自动注音（行方不明→ゆくえふめい），支持笔记、查例句、删除
- 每条收藏句可「🔍找相似」——RAG 引擎召回语料库中语义最接近的例句

### 9. RAG 语义检索
- 字符 bigram TF-IDF 向量索引 + 余弦相似度，本地构建、毫秒查询、语料增长自动重建
- 不只是字面匹配：输入「日本語の勉強」可召回「彼は本気になって勉強を始めた」等语义相关句
- 支持按来源优先级检索（歌词 / 课本 / 语料），也可限定某一本或多本课本，整句输入还会额外显示结构相似分析

## 部署
见 `DEPLOY.md`：Netlify/Firebase 无法运行 Python 后端（已在文档中说明原因），
推荐 **Render 免费部署**（GitHub 直连，全程点鼠标），备选 Hugging Face Spaces / Fly.io，
仓库已含 `requirements.txt` / `Dockerfile` / `render.yaml`，推上去即用。

**数据库与 Git（重要）**：`kanji.db` 是要跟着仓库上 Render 的初始数据源，
所以它必须被跟踪、`.gitignore` 里**不能**写 `*.db`；而 WAL 边车文件
（`kanji.db-wal` / `kanji.db-shm`）必须忽略，否则 pull 必报 would be overwritten。
日常四件事都用托管命令，别再手写 git：

```bash
python dbtool.py status     # 体检：数据量 / WAL 状态 / 与 HEAD 的差异
python dbtool.py save       # 备份本地库（快照 + 只增不减的并集）
python dbtool.py pull       # 安全拉取：备份 → 清理 → pull → 数据并回来
python dbtool.py publish    # 提交 + 推送 kanji.db（Render 自动重新部署）
python dbtool.py verify     # 合并/提交后校验：完整性、孤儿索引、有没有比备份少
```

完整原理、合并规则与 FAQ 见 **`DATABASE.md`**；回归测试：`python test_dbtool.py`。

## 综合能力测评（研究驱动）

在原有挖空/组句基础练习之外，新增 `proficiency_exam.py` 的证据中心测评蓝图：
`foundation`（保留基础算法）、`proficiency`（N级综合）与 `academic`（专业·学术）。
综合卷按明确比例混合语境语法、汉字读音和全文意义理解，每题携带能力领域与证据声明；
结果按题型/领域诊断，不把未经大样本等值的正确率伪装成官方 JLPT 分数。
正式练习采用服务端答案会话：`POST /api/exam/start` → `POST /api/exam/submit`，避免浏览器自报正确；
`GET /api/exam/item-analysis` 聚合选项频次、难度、耗时和信心，为预测后淘汰无效干扰项提供证据。
另有 N3–N1 写作/口语真实任务与分析量规：`GET /api/performance/tasks`、
`POST /api/performance/generate`、`POST /api/performance/rate`；不以选择题冒充产出能力。
多题共用篇章题库支持 `draft → reviewed → approved → retired` 生命周期及六项强制审核，
接口：`GET /api/assessment/passages`、`POST /api/assessment/passages/generate`、
`POST /api/assessment/passages/<id>/review`。原创种子题默认只允许试测，绝不冒充官方真题。
完整研究依据见 [`ASSESSMENT_DESIGN.md`](ASSESSMENT_DESIGN.md)；题目实际来源、版权边界、
覆盖矩阵和质量保证流程见 [`QUESTION_SOURCE_POLICY.md`](QUESTION_SOURCE_POLICY.md)。
测试：`python -m unittest test_proficiency_exam.py test_performance_tasks.py test_assessment_bank.py`。

## 大规模开放语料分片

新增 `corpus_shards.py`：大型语料不再继续塞入可变的 `kanji.db`，而是写入目标 48 MiB、
硬上限 80 MiB 的不可变内容寻址 SQLite 分片；密封后按文件 SHA-256 命名，多设备合并等于
文件集合求并，索引与 manifest 均可重建。支持跨任意数量分片联合查询与文本 UID 去重。
NHK/NHK EASY 因官方条款不允许整库正文复制，注册为 `link_only` 并由代码硬拒绝正文导入；
Tatoeba、Wikimedia 官方 dump 和逐作品确认公版的青空文库作为批量语料来源。
`federated_search.py` 已把主库与分片做候选召回、统一打分、内容去重和来源合并；现有 RAG
也会把只读分片作为 `web` 通道参与排序。调试接口：`GET /api/corpus/federated-search?q=...`；
健康检查：`GET /api/corpus/shards/status?verify=1`。
完整下载、许可、更新、同步、联合检索和精排方案见 [`CORPUS_ARCHITECTURE.md`](CORPUS_ARCHITECTURE.md)。
测试：`python -m unittest test_corpus_shards.py test_federated_search.py test_rag_shards.py`。

## KTV 歌词模式（v2 新增）

去 KTV 前背歌词专用：顶部导航「KTV歌词」。

- **批量导入自动整理**：一次粘贴一首或多首歌词，支持《》【】『』、`曲名：`、`歌名 - 歌手`、`1. 歌名` 编号曲目表、`---` 分隔线等多种格式；空行自动分段（保留段落结构）；重复导入自动去重。
- **大号注音**：复用字幕注音引擎（多音字按上下文取音），假名比字幕模式更大更醒目（加粗＋主题色）；可 A－/A＋ 调字号、一键隐藏注音自测。
- **罗马音支持**：纯罗马音行可一键转片假名显示（Hepburn/Kunrei 均可，支持促音/ん/拗音/长音符）。
- **移动端防误触**：歌词区无任何点击解析，纯滚动浏览；按钮均加大。
- **快速切歌/搜歌**：⏮/⏭ 上一首下一首；搜索框可搜歌名/歌手/歌词内容；歌名、歌词均一键复制（无注音纯文本）。
- **数据库兼容**：老版本 `kanji.db` 升级时自动补建 `songs` 表，原有语料/学习记录不受影响。

API：`GET/POST /api/songs`、`POST /api/songs/import`（支持 `dry_run` 预览）、`GET/POST/DELETE /api/songs/<id>`。

测试：`python3 test_ktv.py`（解析/罗马音/注音/API/旧库迁移全链路）。

## v3 更新

- **KTV 学习模式（默认开启）**：歌词按「意思群」自动分词（分かち書き）——内容词开头断开、助词/助动词跟随前词、连续名词合并（`二人だけの 空が 広がる 夜に`），组间空格、只在意思群之间换行，初学者一眼看清句子结构；工具栏「分词」可关。旧歌词打开时自动补算分词标记（兼容）。

- **助词消歧引擎**：多义助词不再罗列所有可能——と(引用/並列/比較/共同/相手/条件)、に(時間/変化/目的/相手/到達点/受身)、で(原因/手段/範囲/場所)、を(目的語/経過点)、が(主語/対象)、は(主題/対比)、から(起点/原因)，按邻接词的特征＋小词典定位到本句用法，并附「判据」说明；无法判定时才保留多义列表。解释文本不再出现「た」「た」式重复引用。
